## 🔴 HIGH — Logic Bugs (Data Correctness)

### H-1. Profitability dashboard still references `"February 2026"` (HARDCODED)

**File:** `sheets.ts` → `refreshProfitabilityDashboard()` line ~710
**Issue:** The `MONTHS_TO_SCAN` array still has `oneOffTab: "February 2026"` — but we just renamed that tab to `"February"`. The profitability function will silently skip February data because the tab name doesn't match.
**Impact:** February is missing from the profitability dashboard. No error thrown — just silent skip.

### H-2. `getDashboardColIndices()` doesn't handle renamed legacy tabs

**File:** `sheets.ts` → `getDashboardColIndices()` line ~530
**Issue:** Uses `isLegacy = /^\w+\s+\d{4}$/.test(tabName)` to detect legacy layout. Now that "February 2026" is renamed to "February", this regex doesn't match. But `isNewLayout("February")` correctly returns `false`. The dashboard's `getDashboardColIndices` is a separate function that doesn't call `isNewLayout()` — it has its own regex. For "February", it falls through to new layout indices (paymentStatus: 18, subInvoiceAmount: 15, allPaid: 13) but February has 26 columns with legacy indices (paymentStatus: 20, subInvoiceAmount: 17, allPaid: 14).
**Impact:** Dashboard reads wrong columns for February → wrong payment status counts, wrong totals.

### H-3. Recurring revenue dedup is broken (dead code)

**File:** `sheets.ts` → `refreshProfitabilityDashboard()`, recurring section (~lines 790-810)
**Issue:** First pass adds `invoiceNum` to `seenRecurringInvoices` before the revenue check:
```ts
seenRecurringInvoices.add(invoiceNum);
if (invStatus === "paid" && !seenRecurringInvoices.has(invoiceNum)) {
  // ← This never fires — invoiceNum was already added above
}
```
The code then does a second pass with `seenPaidInvoices` to redo it correctly. The first pass's revenue check is dead code, but the second pass works. The second pass `seenUnpaidInvoices` also skips counting `recurringExcluded` for duplicate unpaid invoices, which is correct.
**Impact:** Revenue numbers are actually correct (second pass works), but the first-pass dead code is confusing and fragile. If someone removes the second pass thinking the first handles it, revenue dedup breaks.

### H-4. Recurring tab `formatLinkColumns` uses wrong column indices

**File:** `sheets.ts` → `formatLinkColumns()` line ~310
**Issue:** For non-new-layout tabs, uses `linkCols = [4, 6, 9, 19]` (col T = index 19). But recurring tabs have PDF links in column T (index 19) — that's correct. However, the function also formats column J (index 9) as a link column. On recurring tabs, column J (Client Name) may not always have a hyperlink, but formatting it black won't cause errors, just unnecessary formatting. Minor but wasteful.
**Impact:** Low — cosmetic only.

### H-5. Dashboard `refreshDashboard()` paid detection is double-counting

**File:** `sheets.ts` → `refreshDashboard()` line ~597
**Issue:**
```ts
if (statusLower === "paid" || isPaid) {
  stats.paid++;
```
`isPaid` checks `allPaidVal === "✅"` (All Paid column), while `statusLower` checks Payment Status column. A row where Payment Status = "Paid" AND All Paid = "✅" correctly goes to `paid`. But a row where Payment Status = "Good to Pay" AND All Paid = "✅" (client paid, sub not paid yet) also goes to `paid` because of the `|| isPaid` clause. This misclassifies "Good to Pay" rows as "Paid" when the client has paid but the sub hasn't been released yet.
**Impact:** Dashboard overreports "# Paid" and underreports "# Good to Pay" on new-layout tabs. Legacy tabs unaffected (they don't have separate All Paid column).

## 🟡 MEDIUM — Structural / Design Issues

### M-1. `resolveMode()` only supports `current` and `prev` — no prev-prev

**File:** `env.ts` → `resolveMode()`
**Issue:** Only 4 modes: `current`, `current-r`, `prev`, `prev-r`. There's no way to sync two months back (e.g., February in April). This forced the manual `{"tab":"February"}` call today.
**Impact:** Older months can't be synced via scheduler. Would need manual curl or adding a `prev-2` mode.

### M-2. `MONTHS_TO_SCAN` in profitability dashboard is hardcoded for 2026

**File:** `sheets.ts` → `refreshProfitabilityDashboard()` line ~710
**Issue:** The `MONTHS_TO_SCAN` list hardcodes tab names like `"February 2026"`, `"March"`, `"April"`, etc. It doesn't auto-discover tabs. If January is excluded (per Nathan's request), and future years need tracking, this list must be manually updated.
**Impact:** Won't break, but requires code changes for January inclusion, year rollover, or new tabs. The `refreshDashboard()` function above it auto-discovers tabs — inconsistency.

### M-3. No test coverage

**File:** `package.json` has `"test": "tsx --test test/*.test.ts"` but no test files exist.
**Issue:** Zero automated tests for any adapter, sync logic, or dashboard function.
**Impact:** All validation is manual. Regressions from fixes like today's `isNewLayout` change go undetected until production failure.

### M-4. `addMismatchCF` appends rules without checking if already present

**File:** `function.ts` → `addMismatchCF` handler (~line 770)
**Issue:** Every call to `addMismatchCF` adds new CF rules. There's no check for existing mismatch rules before adding. Running it twice doubles the rule count on every tab.
**Impact:** Rule accumulation over time if endpoint is called repeatedly.

### M-5. GTP tab can't be synced directly — silent failure mode

**File:** `function.ts` → main handler
**Issue:** Posting `{"tab":"Feb - GTP $"}` tries to run it through `runSourceSheetFlow`, which reads Job # from column F on the GTP tab (which has a completely different column layout). The error today ("exceeds grid limits") was because it tried to write new-layout columns to a 26-column GTP tab. There's no guard to reject GTP tabs as sync targets.
**Impact:** Confusing errors. Should either reject GTP tabs explicitly or handle them as a GTP-refresh-only call.

### M-6. Token cache on `/tmp` doesn't persist across Cloud Run cold starts

**File:** `heypros.ts` → `TOKEN_CACHE_PATH = "/tmp/heypros-token-cache.json"`
**Issue:** Cloud Run `/tmp` is ephemeral — cleared on cold start. Every cold start forces a new HeyPros sign-in. With hourly syncs, cold starts are frequent after idle periods.
**Impact:** Unnecessary sign-in calls. Not critical (HeyPros rate limits are generous), but wasteful.

### M-7. `previousMonthTabName()` uses local timezone math that could be fragile

**File:** `env.ts` → `previousMonthTabName()` line ~33
**Issue:** Creates a UTC date at the 1st of the current LA month, then subtracts 1 day to get previous month's last day, then formats with LA timezone. The logic `new Date(Date.UTC(laYear, laMonth, 0))` creates the last day of the previous month (day 0 = last day of prev month), which is correct. However, `laMonth` is derived from `toLocaleString` which may have subtle timezone bugs in Node.js versions. The `formatToParts` approach used in `currentMonthTabName()` is more robust.
**Impact:** Low — works today but fragile under Node.js updates or edge-case timezone transitions.

## 🟢 LOW — Cosmetic / Minor / Technical Debt

### L-1. Duplicate `google.auth.GoogleAuth` instantiation in admin endpoints

**File:** `function.ts` → `fixStaleCF`, `addMismatchCF`, `debugCF`, `deleteRules` handlers
**Issue:** Each admin endpoint does `const { google } = await import("googleapis")` and creates its own `GoogleAuth` instance. The sheets adapter already has `getSheetsClient()`. Could reuse it.
**Impact:** Extra import/auth overhead on admin calls. No functional issue.

### L-2. `RECURRING_AUTO_COL_LETTERS` doesn't match recurring tab column protection

**File:** `sheets.ts` line ~90
**Issue:** Set includes `A` (Date), but recurring tab flow explicitly populates `A` from HeyPros installationStarts. The comment says "A (Date) ... are manual" but the code writes it. The set and the actual write behavior are aligned (A is in the set = writable), but the comment is wrong.
**Impact:** Confusing documentation. No functional issue.

### L-3. Stale comment in `isNewLayout()`

**File:** `sheets.ts` line ~71
**Issue:** Comment still says `"February 2026"` as a legacy tab example, but we just renamed it. Should mention `"February"` (no year suffix) is also legacy.
**Impact:** Misleading for future readers. We did add the `legacyMonths` array, but the header comment doesn't mention it.

### L-4. No error handling for `renameTab` — sheets API could throw on duplicate name

**File:** `sheets.ts` → `renameTab()`
**Issue:** If `to` name already exists, the Sheets API will throw a 400. No pre-check.
**Impact:** Unhandled error returned as 500. Minor — admin endpoint only used manually.

### L-5. `formatDate()` uses UTC month/day — could be off by 1 day near midnight

**File:** `types.ts` → `formatDate()`
**Issue:** Uses `d.getUTCMonth()` and `d.getUTCDate()`. If a date is stored as `"2026-03-31T23:00:00-07:00"` (LA time near midnight), UTC would be `2026-04-01T06:00:00Z` — formatted as `4/1/2026` instead of `3/31/2026`.
**Impact:** Dates could be off by 1 day in rare edge cases. Both Jobber and HeyPros typically use ISO strings with timezone info, so this depends on their API formatting.

### L-6. `Jobber.amount` is in different units between Jobber and HeyPros

**File:** `function.ts` and `types.ts`
**Issue:** Jobber's `invoices.amounts.total` is in **dollars** (from the API response). HeyPros `jobInvoices.amount` is in **cents** (divided by 100 with `formatAmount`). The `JobberPaidJob.amount` field stores the raw value from Jobber. In `refreshProfitabilityDashboard`, `parseDollarAmount` is used on the Sub Invoice Amount cell value (already formatted as "$X.XX"), so this works correctly for the dashboard. But in `runSourceSheetFlow`, `values.M = inv.amount.toFixed(2)` writes Jobber's amount directly — and the Jobber API `amounts.total` is already in **dollars with decimals** (not cents).
**Actually:** Checking closer — Jobber `amounts.total` is in dollars (float, e.g. 1234.56). The code writes `inv.amount.toFixed(2)` which is correct for dollars. HeyPros amounts are in cents, correctly divided by 100 via `formatAmount`. Units are handled correctly but undocumented — easy to confuse.
**Impact:** No functional bug, but confusing. Should add a comment on the `amount` field clarifying units.

### L-7. `logSyncResult` doesn't log the Dashboard refresh after tab syncs

**File:** `function.ts` line ~975
**Issue:** After every tab sync, a separate Dashboard log entry is appended. This doubles the Log entries per sync (one for the tab, one for Dashboard). The Dashboard log entry duplicates the elapsed time from the tab sync.
**Impact:** Log clutter. Dashboard refresh is an internal step, not a separate sync event.

### L-8. `extendTabCF` uses `updateConditionalFormatRule` with full rule spread

**File:** `sheets.ts` → `extendTabCF()` line ~1520
**Issue:** Spreads `...rule` which includes the entire rule object from the API response, which may have additional read-only fields that could cause issues on write. In practice the Sheets API ignores unknown fields, so this works.
**Impact:** Fragile but functional.
